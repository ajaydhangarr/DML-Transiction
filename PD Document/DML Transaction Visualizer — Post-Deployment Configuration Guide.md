# DML Transaction Visualizer

## Post-Deployment Configuration Guide

This guide contains the required one-time configuration steps to enable Tooling API callouts after installing the **DML Transaction Visualizer** package in a Salesforce org.

---

## Prerequisites

Before starting the configuration:

- The DML Transaction Visualizer package must be installed successfully.
- The user performing this setup must have the required Salesforce Setup permissions to create and configure:
  - External Client Apps
  - Auth Providers
  - External Credentials
  - Named Credentials
  - Permission Sets
- The Salesforce org should have **My Domain** configured.
- Access to a Salesforce user account that can authorize the OAuth connection is required.

---

# Step 1 — Create an External Client App

1. Go to **Setup**.
2. In **Quick Find**, search for **External Client Apps**.
3. Open **External Client Apps**.
4. Click **New External Client App**.

Enter the following details:

| Field                    | Value                  |
| ------------------------ | ---------------------- |
| External Client App Name | `DML Tooling App`      |
| API Name                 | `DML_Tooling_App`      |
| Contact Email            | `<your email address>` |

### Enable OAuth Settings

Enable the OAuth settings for the External Client App and configure:

| Field        | Value                                                          |
| ------------ | -------------------------------------------------------------- |
| Callback URL | `https://login.salesforce.com/services/oauth2/callback`        |
| OAuth Scope  | `Manage user data via APIs (api)`                              |
| OAuth Scope  | `Perform requests at any time (refresh_token, offline_access)` |

5. Click **Save**.
6. Open the External Client App details.
7. Locate the **Consumer Key** and **Consumer Secret**.
8. Copy and securely store both values. They are required in Step 2.

> **Note:** Depending on the Salesforce release and org configuration, the External Client App interface may use slightly different labels. Use the OAuth configuration section within the External Client App to configure the callback URL and scopes.

---

# Step 2 — Create an Auth Provider

1. Go to **Setup**.
2. In **Quick Find**, search for **Auth. Providers**.
3. Click **New**.
4. Select **Salesforce** as the Provider Type.

Configure the following:

| Field                  | Value                                                    |
| ---------------------- | -------------------------------------------------------- |
| Name                   | `DML Tooling Auth`                                       |
| URL Suffix             | `DMLToolingAuth`                                         |
| Consumer Key           | `<Consumer Key from Step 1>`                             |
| Consumer Secret        | `<Consumer Secret from Step 1>`                          |
| Authorize Endpoint URL | `https://login.salesforce.com/services/oauth2/authorize` |
| Token Endpoint URL     | `https://login.salesforce.com/services/oauth2/token`     |
| Default Scopes         | `api refresh_token`                                      |

5. Click **Save**.
6. On the Auth Provider detail page, locate the generated **Callback URL**.
7. Copy the Callback URL.
8. Go to **Setup → External Client Apps**.
9. Open **DML Tooling App → Edit**.
10. Replace the temporary Callback URL from Step 1 with the Callback URL generated by the Auth Provider.
11. Save the External Client App.

---

# Step 3 — Create an External Credential

1. Go to **Setup**.
2. Search for **Named Credentials**.
3. Open the **External Credentials** tab.
4. Click **New**.

Configure:

| Field                    | Value                  |
| ------------------------ | ---------------------- |
| Label                    | `DML Tooling External` |
| Name                     | `DML_Tooling_External` |
| Authentication Protocol  | `OAuth 2.0`            |
| Authentication Flow Type | `Browser Flow`         |
| Scope                    | `api refresh_token`    |
| Identity Provider        | `DML Tooling Auth`     |

5. Click **Save**.

---

# Step 4 — Create the `DML_Admin` Principal

1. Open the **`DML_Tooling_External`** External Credential.
2. Scroll to the **Principals** section.
3. Click **New**.

Configure:

| Field           | Value             |
| --------------- | ----------------- |
| Parameter Name  | `DML_Admin`       |
| Sequence Number | `1`               |
| Identity Type   | `Named Principal` |

4. Click **Save**.

> **Important:** The `DML_Admin` principal must be authenticated before the package can use the Tooling API connection.

---

# Step 5 — Create a Named Credential

1. Go to **Setup → Named Credentials**.
2. Click **New**.
3. Configure the following:

| Field                         | Value                        |
| ----------------------------- | ---------------------------- |
| Label                         | `DML Tooling`                |
| Name                          | `DML_Tooling`                |
| URL                           | `<Salesforce My Domain URL>` |
| External Credential           | `DML_Tooling_External`       |
| Generate Authorization Header | **Checked**                  |

The URL must point to the **Salesforce org where the package is installed**.

### Configure Managed Package Access

In the **Managed Package Access** section:

- Add the package namespace under **Allowed Namespaces for Callouts**:

```text
dmlviz
```

> **Important:** The `dmlviz` namespace is required so that the package's namespaced Apex code can use the Named Credential for callouts.

4. Click **Save**.

---

# Step 6 — Create and Assign the Permission Set

## Create Permission Set

1. Go to **Setup**.
2. Search for **Permission Sets**.
3. Click **New**.
4. Set the Label to:

```text
DML Tooling Access
```

5. Click **Save**.

## Grant External Credential Principal Access

1. Open the **DML Tooling Access** Permission Set.
2. Open **External Credential Principal Access**.
3. Click **Edit**.
4. Move the following principal to **Enabled External Credential Principals**:

```text
DML_Tooling_External – DML_Admin
```

5. Click **Save**.

## Assign the Permission Set

1. Click **Manage Assignments**.
2. Click **Add Assignment**.
3. Select the user who will authenticate and use the DML Transaction Visualizer.
4. Click **Assign**.

> **Important:** The user who authenticates the `DML_Admin` principal must have the `DML Tooling Access` Permission Set assigned.

---

# Step 7 — Authenticate the `DML_Admin` Principal

The `DML_Admin` principal must be authenticated to establish the OAuth connection.

1. Go to **Setup → Named Credentials**.
2. Open the **External Credentials** tab.
3. Open:

```text
DML_Tooling_External
```

4. In the **Principals** section, locate:

```text
DML_Admin
```

5. Open the action menu next to `DML_Admin`.
6. Select **Authenticate**.
7. Sign in using the Salesforce user who has been assigned the **DML Tooling Access** Permission Set.
8. Click **Allow** when prompted.

### Verify Authentication

Confirm that the status of the `DML_Admin` principal is:

```text
Authenticated
```

> **Important:** Do not proceed until the `DML_Admin` principal shows **Authenticated**.

---

# Step 8 — Verify the Configuration

After completing all configuration steps, verify the following:

| Configuration        | Expected Value / Status                |
| -------------------- | -------------------------------------- |
| External Client App  | `DML Tooling App`                      |
| Auth Provider        | `DML Tooling Auth`                     |
| External Credential  | `DML_Tooling_External`                 |
| Principal            | `DML_Admin`                            |
| Principal Status     | **Authenticated**                      |
| Named Credential     | `DML_Tooling`                          |
| Permission Set       | `DML Tooling Access`                   |
| Package Namespace    | `dmlviz`                               |
| Named Credential URL | Current Salesforce org's My Domain URL |

Once all items are configured correctly, the DML Transaction Visualizer is ready to make the required Tooling API callouts.

## Post-Deployment Checklist

Use this checklist to confirm that the configuration is complete:

- [ ] External Client App created
- [ ] Consumer Key and Consumer Secret configured in Auth Provider
- [ ] Auth Provider Callback URL added to the External Client App
- [ ] External Credential created
- [ ] `DML_Admin` principal created
- [ ] Named Credential created
- [ ] Salesforce org My Domain URL configured
- [ ] `dmlviz` added to Allowed Namespaces for Callouts
- [ ] `DML Tooling Access` Permission Set created
- [ ] `DML_Admin` principal access enabled in the Permission Set
- [ ] Permission Set assigned to the required user
- [ ] `DML_Admin` principal authenticated
- [ ] Principal status shows **Authenticated**
- [ ] Configuration verified successfully
